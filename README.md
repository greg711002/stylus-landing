# Stylus — landing page

A dependency-free rebuild of the Stylus (mystylus.ai) affiliate landing page: plain
HTML, one stylesheet, one small script, local fonts and local images. No build step,
no framework, no CDN. Ships as an installable, offline-capable PWA in **sixteen
languages**: English, Polish, Russian, Simplified Chinese, Spanish, Hindi, Portuguese
(BR), Bengali, French, German, Japanese, Arabic (RTL), Korean, Italian, Turkish and
Indonesian.

**Live site:** https://greg711002.github.io/stylus-landing/ (GitHub Pages, project
site under the `/stylus-landing/` sub-path — all page links are relative, hreflang
URLs absolute).

## Preview

```bash
node serve.mjs          # http://127.0.0.1:8099  (English), /pl/ /ru/ /zh/ /es/ /hi/ /pt/ /bn/
                        # /fr/ /de/ /ja/ /ar/ /ko/ /it/ /tr/ /id/
node serve.mjs 3000     # any other port
```

Do not open `index.html` from the file system if you want to test the PWA: service
workers need an `http(s)` origin. Everything else works from `file://` as well.

## Structure

```
index.html               English page; markup + inline SVG icon sprite at the top of <body>
pl/index.html            Polish page, generated by tools/make-locales.mjs — do not hand-edit
ru/index.html            Russian page, same generator — do not hand-edit
zh/index.html            Simplified Chinese page, same generator — do not hand-edit
es/index.html            Spanish page, same generator — do not hand-edit
hi/index.html            Hindi page, same generator — do not hand-edit
pt/index.html            Portuguese (BR) page, same generator — do not hand-edit
bn/index.html            Bengali page, same generator — do not hand-edit
fr/index.html            French page, same generator — do not hand-edit
de/index.html            German page, same generator — do not hand-edit
ja/index.html            Japanese page, same generator — do not hand-edit
ar/index.html            Arabic page, same generator, <html dir="rtl"> — do not hand-edit
ko/index.html            Korean page, same generator — do not hand-edit
it/index.html            Italian page, same generator — do not hand-edit
tr/index.html            Turkish page, same generator — do not hand-edit
id/index.html            Indonesian page, same generator — do not hand-edit
locales/en.json          English copy, 72 flat keys (source of truth for the generator)
locales/pl.json          Polish copy, same 72 keys, same order
…                        one JSON per language, same 72 keys, same order (16 files total)
manifest.webmanifest     web app manifest (install name, colors, four icons)
sw.js                    service worker: shell precache, offline navigation fallback
offline.html             self-contained offline page (no external asset references)
assets/css/styles.css    design tokens + layout, breakpoints at 900/860/700/600/375px,
                         per-script font fallbacks and script-specific typography
assets/js/main.js        nav toggle + nav dropdown, language dropdown, reviews carousel,
                         scroll reveals, footer year, RTL-aware sliding,
                         language-independent base URL + service worker registration
assets/fonts/            Stolzl Light/Regular/Medium/Bold (.ttf, self-hosted)
assets/img/              logos, hero device shot, feature art, avatars, team, partners,
                         PWA icons (icon-*.png, icon-maskable-*.png)
serve.mjs                tiny static server used for local preview
check.mjs                integrity check: references, anchors, sprites, all locales, PWA
tools/make-locales.mjs   regenerates the localised pages from index.html + locales/*.json
```

`tools/make-locales.mjs` is the only build-ish script, and it is optional: the generated
localised pages are committed. Its `LOCALES` table is the single source of truth for the
output folders, the `hreflang` set, the `og:locale` alternates and the switcher order —
add a row there and re-run to add a language. If you change English markup or any locale
file, re-run `node tools/make-locales.mjs`; it rewrites every localised page, re-declares
`og:locale`, every `hreflang` and the fifteen-item language menu on all sixteen pages, and
fails loudly (exit 1) on any string it could not apply, so no half-translated page can
slip through. `node tools/make-locales.mjs --dry` reports without writing.

The generator replaces an English string only when it is a **whole text node** or a
**whole attribute value** in the English page, so a localised phrase never lands inside a
longer English sentence by accident. That also means a new visible label can be localised
for free by writing its English wording exactly as an existing key's value: the header
dropdown's "Menu" summary reuses the `aria_menu_toggle` key, which already carries the
translation in all sixteen dictionaries.

## Languages

- English lives at `/`, then Polish `/pl/`, Russian `/ru/`, Simplified Chinese `/zh/`,
  Spanish `/es/`, Hindi `/hi/`, Portuguese (BR) `/pt/`, Bengali `/bn/`, French `/fr/`,
  German `/de/`, Japanese `/ja/`, Arabic `/ar/`, Korean `/ko/`, Italian `/it/`, Turkish
  `/tr/` and Indonesian `/id/`. All sixteen are real, statically generated pages with
  their own `<html lang>`, `<title>`, meta description and Open Graph tags.
- **Header navigation** — the two in-page links ("How it works", "Reviews") sit in a
  native `<details class="nav-picker">` dropdown behind a "Menu" summary; the selected
  language is a sibling `<details class="lang-picker">` dropdown with the other fifteen
  languages as plain `<a class="lang">` links. Both are `<details>`/`<summary>` rather
  than JS toggles, so the links exist in the HTML and crawlers can follow them. Opening
  one closes the other: the two panels are absolutely positioned in the same band under
  the navbar, so a small script listens for the `toggle` event and shuts the sibling
  picker, which keeps them from ever being drawn on top of each other. There is
  deliberately **no** `Accept-Language` redirect: it would hide the English page from
  search engines and break deep links.
- Below 860 px both dropdowns stop being dropdowns: the nav summary is hidden so the
  hamburger opens a flat list of the two links, and the language list becomes a static
  4-column grid inside the same panel. Nothing nests one dropdown inside another on a
  phone.
- **RTL** — Arabic is the only right-to-left locale. It gets `<html dir="rtl">`, a
  `[dir="rtl"]` CSS block (navbar auto-margins, list indents, icons), an Arabic font
  stack, and an RTL-aware carousel: `main.js` reads
  `document.documentElement.dir === 'rtl'` and flips the `translate3d` sign, the arrow-key
  direction and the swipe direction. Both dropdowns use logical properties
  (`inset-inline-start` / `inset-inline-end`), so each panel opens inward toward the page
  centre in either direction.
- Reciprocal `hreflang` (all sixteen codes plus `x-default`) and one
  `og:locale:alternate` per other language are declared on every page.
- Publishing on the real domain still needs three absolute URLs added by hand, which a
  local rebuild cannot know: `og:url`, an `og:image` at 1200×630 and a `<link rel="canonical">`
  per language (see the comment in the `<head>`). Until then a shared link has no preview
  card. The language menu and `hreflang` use root-relative paths (`/pl/`, `/ru/`, `/`,
  …), so the set must be deployed at the domain root — in a subfolder all of them need
  rewriting.
- One caveat for the client: the testimonials were translated from the original English
  and should be signed off before launch — non-English readers generally expect a visible
  note such as *„Opinie przetłumaczone z języka angielskiego"*,
  *«Отзывы переведены с английского языка»*, *«Reseñas traducidas del inglés»*,
  *«Avaliações traduzidas do inglês»*, 评论由英文翻译而来, *«समीक्षाएँ अंग्रेज़ी से अनूदित हैं»*,
  *«রিভিউগুলি ইংরেজি থেকে অনূদিত»*, *«Avis traduits de l'anglais»*,
  *„Bewertungen aus dem Englischen übersetzt"*, 英語から翻訳されたレビュー,
  *«المراجعات مترجمة من الإنجليزية»*, 영어에서 번역된 후기, *«Recensioni tradotte dall'inglese»*,
  *„İngilizceden çevrilmiş yorumlar"*, *"Ulasan diterjemahkan dari bahasa Inggris"*.
- Six university wordmarks (`assets/img/uni-*.svg`) are drawn as SVG paths, so their
  names cannot be translated; they stay in Latin script in every locale, as in print.
- **Fonts** — the self-hosted Stolzl covers Latin and Cyrillic only. The body font stack
  therefore falls back per script, in this order: `Noto Sans SC / PingFang SC /
  Microsoft YaHei / Hiragino Sans GB` for Chinese, `Noto Sans Devanagari / Nirmala UI /
  Mangal` for Hindi, `Noto Sans Bengali / Bangla MN` for Bengali, `Noto Sans Arabic /
  Geeza Pro / Tahoma` for Arabic, then `system-ui / -apple-system / sans-serif`.
  Japanese and Korean are deliberately left to that last group, where the OS picks its
  own JP/KR face (Hiragino/Yu Gothic, Apple SD Gothic Neo/Malgun Gothic) — naming
  `Noto Sans JP` there would pull a Latin-first family ahead of the native one for the
  Kana/Hangul runs. English, Polish, Russian, German, French, Spanish, Portuguese,
  Italian, Turkish and Indonesian are unaffected (Latin resolves in Stolzl first).
- **Script typography** — the Latin design's negative letter-spacing and tight heading
  line-heights clip Devanagari/Bengali matras, read wrong in CJK and are unnecessary in
  Arabic, so a "Script-specific typography" block in `styles.css` zeroes `letter-spacing`
  on headings for `zh`/`ja`/`ko`/`hi`/`bn`/`ar` and raises `line-height` to `1.7` for
  CJK body, `1.65` Hindi/Bengali body, `1.75` Arabic body, with headings at `1.32`
  (Hindi/Bengali), `1.35` (Japanese/Korean) and `1.4` (Arabic).
- Long-word safety: `overflow-wrap: break-word` on `body` plus `minmax(0, 1fr)` grid tracks
  in the `max-width: 900px` block keep a long translated word — Russian
  «персонализированно» was the case that broke it — from widening the page past a 320 px
  viewport. A `1fr` track floors at min-content, and `break-word` alone cannot shrink it.
- **Dropdown width** — sixteen 2-letter pills would measure ~656 px in one row and push
  the navbar into overflow on a laptop, which is why the switcher became a dropdown
  instead of growing a third row of pills. A measurement pass over 16 locales × 13
  viewport widths (320–1440 px), with each dropdown opened, found no overflow: the
  language panel is 200 px wide with 34×32 px items, the nav panel 216 px with 200×44 px
  items, and neither overlaps the Log in / Try it buttons nor escapes the viewport at any
  width, in LTR or RTL.

## PWA

The site installs to the home screen and works offline after the first visit.

- **Icons** — `icon-192/512.png` (purpose `any`) and `icon-maskable-192/512.png` are
  rasterised from `assets/img/logo-mark.svg` (white mark on `#2b3f6c`). The maskable
  variants draw the mark at 55% of the canvas so it stays inside the safe circle; do not
  replace them with the plain icons, Android will crop the glyph.
- **Precache** — `sw.js` precaches 91 URLs: every locale document and its directory URL
  (sixteen languages × 2), the offline page, the manifest, CSS, JS, the four fonts and
  **every** image in `assets/img` (the whole directory is only ~2.1 MB). Precaching the
  images is what makes the offline page actually look right instead of showing broken
  pictures.
- **Strategy** — navigations are network-first with a cache fallback and, failing that,
  `offline.html`; static assets are cache-first with a background refresh. Anything not
  precached is cached on first use.
- **Updating** — bump `VERSION` in `sw.js` (currently `'v5'`). The cache name is
  `stylus-` + version, and activation deletes every older `stylus-*` cache, so a new
  version forces a clean refresh. `skipWaiting()` + `clients.claim()` mean the update is
  picked up on the next load without a hard reload.
- **Manifest language** — a manifest carries a single language set, so this one is
  English (`"lang": "en"`, English `name`). Install names in the other fifteen languages
  would need a separate manifest per locale (e.g. `pl/manifest.webmanifest` with
  `"start_url": "./"`, referenced from that page); that is not wired up today.
- **Serving** — `start_url` and `scope` are `"./"`, so the app can live in a subfolder.
  Two host requirements: serve `.webmanifest` as `application/manifest+json` (Chrome
  refuses `application/octet-stream`; `serve.mjs` already maps it) and serve over
  HTTPS in production (service workers are blocked on plain HTTP, `localhost` excepted).
- `offline.html` must stay self-contained. It is served for any failed navigation,
  including every localised path (`/pl/`, `/ar/`, …), where a relative `assets/…` path
  would resolve to `/pl/assets/…` and break. It carries one short line per language
  (sixteen `<p lang>` paragraphs).

## Notes on the content

- All copy, headings, reviews and numbers are original translations of the English
  source; the brand name "Stylus AI" stays Latin script in every locale.
- Affiliate identifiers (`?ref=…&affiliate_type=edugram`), the UTM-forwarding script and
  tracking pixels were removed; every outbound link now points at the plain
  `mystylus.ai` / social URL. The manifest `start_url` carries no tracking parameter
  either. `check.mjs` reports the full external-link inventory.
- The carousel is a plain CSS transform slider. It shows 3 / 2 / 1 reviews per view,
  keeps the dots in sync, re-snaps to a page boundary on resize, and responds to
  arrow keys, swipe, dots and the arrow buttons — mirrored in RTL.
- Both dropdowns close on Escape (returning focus to their summary), on a click outside
  and on the breakpoint crossing, so no panel can be left open behind a resized window.
- Motion respects `prefers-reduced-motion`: the logo marquee stops and the team grid
  collapses to a single column.
- Accessibility: one `h1`, landmark regions, `aria-current` on the active language and the
  active dot, labelled carousel controls, native `<details>`/`<summary>` disclosure
  widgets (keyboard-operable without extra ARIA), `aria-expanded` on the mobile hamburger,
  visible focus rings, 24 px minimum touch targets (WCAG 2.5.8 AA) and body text at
  ≥ 4.5:1 contrast (WCAG 1.4.3 AA).

## Checks

```bash
node check.mjs          # static integrity, all locales, manifest + service worker
```

`check.mjs` resolves every `src`/`href`/`url()` against the directory of the page that
uses it, verifies anchors and sprite symbols, compares the locale files key by key,
flags any English string that survived into a localised page, and validates the PWA layer
(manifest fields and real PNG dimensions against their declared `sizes`, every precached
URL present on disk, the required service-worker behaviours, and the self-containment of
`offline.html`). It also fails on a stale locale folder that no longer belongs to any
configured language. Its `LOCALES` table mirrors the generator's; keep the two in sync.

Rendered verification lives outside this folder, in `C:\mcp\tools\verify` (Playwright +
Chrome for Testing), so the deliverable stays dependency-free:

```bash
# layout/interaction assertions, once per locale (38 checks each):
for loc in en pl ru zh es hi pt bn fr de ja ar ko it tr id; do
  SHOTS_DIR=shots/$loc node verify.mjs http://127.0.0.1:8099/$( [ $loc = en ] || echo "$loc/" )
done
# section screenshots, then pixel/text overlap analysis, per locale:
SITE=http://127.0.0.1:8099/ar/ OUT=C:/mcp/tools/verify/shots/ar node sections.mjs
SITE=http://127.0.0.1:8099/ar/ SHOTS=http://127.0.0.1:8100/shots/ar/ node layout.mjs
node pwa.mjs                                 # manifest, service worker, offline, installability
node probe-nav.mjs                           # nav dropdown: 16 locales × 13 widths, 10 behaviours
node probe-switcher.mjs                      # language dropdown: 16 locales × 13 widths
node make-icons.mjs                          # regenerate the four PNG icons from logo-mark.svg
```

`layout.mjs` reads its screenshots from `SHOTS` (default `http://127.0.0.1:8100/shots/`,
served by `serve-shots.mjs`); point it at `…/shots/<locale>/` so each language keeps its
own set. `SHOTS_DIR=shots/<locale>` on `verify.mjs` keeps the three screenshots it takes
from overwriting another language's. Both servers must be up: `node serve.mjs 8099` for
the pages and `node serve-shots.mjs 8100` for the images `layout.mjs` re-reads.

`probe-nav.mjs` drives the nav dropdown through open-by-click, close-on-link,
close-on-Escape (with focus back on the summary), close-on-outside-click and
close-on-resize — and then checks, with a second dropdown in the page, that opening one
closes the other in both directions and that the closed panel is not painted.

38/38 × 16, `layout.mjs` 7/7 × 16, `pwa.mjs` 127/127, `probe-nav.mjs` and
`probe-switcher.mjs` 0 problems (16 locales × 13 widths, 320–1440 px, LTR and RTL).
